# 发布说明 1.1.0-0066（字幕队列设置回到「任务」标签）

> 版本：**1.1.0-0066** · 日期：2026-11-20
> 上一版：[1.1.0-0065](RELEASE_NOTES_v1.1.0-0065.md)（转换 VAAPI 硬编硬解）
> 主题：修掉 v0060 设置页瘦身造成的“**字幕并发无处可设**”，并把已完成任务保留上限一起放回可调

## 1. 问题：字幕并发在界面上消失了

v0060「设置页瘦身」把设置页里一整批纯参数删掉了，其中就包括「字幕并发任务数」和「已完成字幕任务保留上限」。
但后端键、校验范围（`subtitle_concurrency` 1..4、`subtitle_job_limit` 20..1000）与“保存后立即生效”的逻辑全部保留
—— 结果是界面上再也找不到设置并发的地方，只能自己调 `PUT /api/settings`。

更隐蔽的是 QA 也没兜住：v0060 把静态检查 `FE-SUBTITLE-CONCURRENCY` 降级成“只要后端两个键在就算过”，
所以它一直绿灯，回归被漏了过去。

## 2. 修复：把队列设置放到「字幕 → 任务」标签

与 v0060 之后“操作参数跟着功能页、设置页只留凭据与总开关”的原则一致，这两个**队列级**参数放到了
「字幕 → 任务」标签的任务明细卡片顶部（`#subtitleQueueSettings`）：

| 控件 | 范围 | 默认 | 生效方式 |
|---|---|---|---|
| 并发任务数 | 1–4 | 1（串行，最稳） | 立即调整 worker 池；排队任务马上按新并发调度 |
| 已完成任务保留上限 | 20–1000 | 200 | 立即更新上限；下一次清理按新上限裁剪，**不再需要重启套件** |

- 改完即保存（`change` 触发 `PUT /api/settings`），成功 toast 提示、失败回滚控件并展示后端中文错误。
- **调小并发不打断正在执行的任务**：多余 worker 在任务边界退出，当前任务跑完再结束。
- 保留上限的 LRU 只删任务目录与 DB 记录，**写回视频旁的 srt 永不删除**。
- 批次进度摘要新增「并发 N」；进入页面/保存设置后自动回填（不会再出现“控件显示 1、实际是 2”）。
- 设置页「云端字幕」仍只保留凭据与总开关（启用 / ASR / LLM / 默认音轨 / 监控目录），不重复展示这两项。

## 3. 后端

- `SubtitleService.apply_settings()` 现在同时应用并发与保留上限（新增 `_clamp_job_limit`，规范到 20..1000，非法值回退 200）。
- 补丁里没有 `subtitle_job_limit` 时保持原值，避免“只改并发”误改上限。
- `PUT /api/settings` 在补丁包含任一键时调用 `apply_settings()`。
- 新增常量 `config.SUBTITLE_JOB_LIMIT_MIN/MAX`，设置校验、`/api/meta` 与前端提示共用同一组范围。
- `GET /api/meta` 的 `subtitle` 新增 `job_limit_min` / `job_limit_max`（前端据此渲染输入框范围）。

## 4. 测试与 QA

- 单元测试 **898 OK（6 skipped）**；新增 3 项：保留上限立即生效/越界钳制、无该键时不动上限、调小上限后置清理标记并按新上限裁剪。
- 静态检查 **258 PASS / 0 FAIL**；`FE-SUBTITLE-CONCURRENCY` 重新要求“界面上真有控件”，并新增 `FE-SUBTITLE-JOB-LIMIT`。
- e2e **267 PASS / 0 FAIL / 1 UNVERIFIED**（Windows 符号链接用例）；新增 SUB-36..39：设置回传两个键、meta 暴露范围、保存 50、越界 400。
- 真机 Chromium 探针（dev 后端 + 真实 `index.html`）：控件渲染 4 个并发选项（默认「1（串行）」）、保留上限 200/20–1000；
  改成 2 与 300 后 `GET /api/settings` 立即反映；输入 5 时回滚为 300 并显示「保留上限必须是 20–1000 的整数。」，无 console 报错。
- 顺带修了一个**环境相关的测试脆弱点**：`test_external_ffmpeg_settings_meta_diagnostics` 原先把 `python.exe` 拷贝当
  “非 ffmpeg 可执行文件”桩，Windows 上副本缺 `python3xx.dll` 会弹系统错误框并卡住 `CreateProcess`，导致 `/api/meta` 探测超时
  （在 v0065 代码上也能复现，属既有问题）。改为用系统 `cmd.exe` 作桩后 1s 内完成，整套单测耗时从 6 分钟降到 3 分钟以内。

## 5. 兼容性与升级

- 无新增/删除设置键，默认值不变；SQLite schema 仍 **v11**，无数据迁移。
- 升级后不需要重启套件即可调整这两项；旧配置（例如历史上设置过并发 2）继续生效。
- 产物：`dist/DuplicateCleaner-1.1.0-0066.spk`（97,160 KB）。
