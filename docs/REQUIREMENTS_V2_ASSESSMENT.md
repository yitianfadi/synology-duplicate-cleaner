## 0. 结论摘要

需求共 **12 组、30 条子项**：

| 结论 | 条数 | 说明 |
|---|---|---|
| 已实现，本轮只需补强或不动 | 3 | 快速过滤漏斗、忽略符号链接、部分预览能力 |

**必须先说清楚的 5 件事**（详细理由见 §3）：

1. **"增量扫描只比对上次扫描后新增/修改的文件"做不到**——那会漏掉"新文件与旧文件重复"这个最主要场景。真正可行的是**哈希缓存 + 内容未变不重算**（枚举仍要 stat 全部文件），再额外提供"仅看本次新增的重复"视图。收益仍然很大：第二次扫描的全量读取 IO 接近 0。
2. **"权限一键向导"无法真的自动配好权限**——套件以非 root 用户 `duplicatecleaner` 运行，改不了共享文件夹 ACL，DSM 也没有套件提权接口。能做的是**权限体检 + 精确到 DSM 界面/命令的指引**。
3. **相似视频无法承诺识别"不同剪辑版本/花絮"**——能做到"同源不同压制（分辨率/码率/封装不同）"高召回，剪辑、加片头片尾、水印台标只能分档给置信度，仍必须人工复核。
4. **硬链接合并可行但不可逆**——合并后所有路径共享同一内容，回收站也恢复不出独立副本。所以做成**独立的"合并为硬链接"操作**（不是删除的替代项），默认关闭、逐组确认，并提供"复制副本恢复"。
5. **DSM 系统通知可行**（真机确认 `/usr/syno/bin/synodsmnotify` 存在且 setuid root，支持 `-l info/warn/error` 与 `@administrators` 组），但只在用户登录 DSM 时可见。

## 2. 逐项评估

### 2.1 扫描 · 优化 1：增量扫描与哈希缓存

- **需求原文**：支持增量扫描，仅对比上次扫描后新增、修改的文件；缓存哈希库，无需每次全量计算 SHA-256。
- **结论**：**需改法可行**（原文的"仅对比新增/修改文件"不可行）。
- **为什么原文不可行**：重复检测的价值恰恰在"跨时间比对"。如果第二次扫描只看新增/修改文件：
  - 新文件与**未变化旧文件**内容相同 → 发现不了（最常见场景）；
  - 旧文件被删除/重命名 → 感知不到；
  - 两个旧文件中的一个被修改后与另一个变重复 → 漏检。
- **可行方案（v0043）**：
  1. 新增 SQLite 表 `hash_cache`（schema v8）：主键 `(dev, ino)`，存 `path, size, mtime_ns, quick_hash, full_hash, algo, sampled_at`。
  2. 扫描每个阶段先查缓存：`(dev, ino, size, mtime_ns)` 完全一致 → 复用 `quick_hash`/`full_hash`，**不读文件内容**；否则重算并回写。
  3. 枚举阶段仍 `stat` 全部文件（10 万文件约数十秒），但哈希阶段读取量降到接近 0（仅变化文件）。
  4. 结果里给每个文件打 `first_seen_scan_id` / `changed_since_scan_id`，新增"本次新增的重复"筛选与摘要（满足"只看增量"的直觉需求）。
  5. 缓存失效条件：algo 变更、采样大小变更、`mtime_ns`/`size`/`inode` 变化、缓存条目超过 TTL/上限（LRU 清理）。
- **风险**：① inode 复用（文件删除后同名新文件复用 inode）→ 用 `mtime_ns + size + path` 三重比对；② NAS 上 mtime 精度为 1 ns（Btrfs）足够；③ 若文件内容被"原地修改且 mtime 不变"（极少数工具）→ 与现有一致性风险相同，删除前仍全量重校验，安全性不降低。
- **验收**：同一目录连续扫两次，第二次 `hashed_bytes` 应为 0 或仅变化文件；两次结果组数/文件数一致；删除前重校验仍通过。

### 2.2 扫描 · 优化 2：丰富保留策略

- **需求原文**：除保留最晚创建外，支持保留体积最大、按路径优先级、优先保留带字幕/内嵌音轨版本，同时支持按修改时间、访问时间、文件名优先级选择保留文件。
- **结论**：**可行**（访问时间有可靠性限制）。
- **方案（v0043）**：把 `keep_mode` 从"枚举"升级为**规则链** `keep_rules`（有序列表，逐条比较，前一条平局才看下一条）：
  - 内置规则：`created_latest`（默认）/ `created_earliest` / `mtime_latest` / `mtime_earliest` / `size_largest` / `size_smallest` / `path_priority`（有序目录/路径前缀列表，越靠前优先）/ `filename_priority`（正则/通配符加权，如 `*2160p*` > `*1080p*`、`CHS` 优先）/ `has_subtitle_stream` / `has_audio_streams` / `atime_latest`（默认不启用）。
  - 命中"带字幕/内嵌音轨"需要在候选组内跑 FFmpeg 探测（只对已确认重复组内的文件，数量少），结果进 `media_probe_cache` 表复用。
  - 无法可靠取得 btime 时仍沿用现有安全降级（整组 mtime + 标记 `time_fallback`）。
- **限制**：`atime` 在 DSM 默认 `relatime` 下不可靠（只在特定访问后更新）→ 该规则默认关闭并在 UI 标注"不可靠，仅作参考"；`filename_priority` 需要用户懂正则 → 提供预设模板（分辨率/语言/版本后缀）+ 自定义。
- **验收**：每组给出 `keep_reason` 与 `rule_index`；规则链平局 → 转人工（不猜）。

### 2.3 扫描 · 优化 3：预扫描快速过滤

- **结论**：**已实现**（大小分组 → 头尾采样 → 全量哈希，正是需求描述的三级漏斗）。
- **本轮只做增强（v0043，低风险）**：
  - 大文件（≥ `large_file_threshold`，默认 256 MB）采样改为 **头 + 中 + 尾三段**（当前只有头尾）；
  - 采样阶段缓存复用（`hash_cache` 同时缓存 `quick_hash`）；
  - 统计里区分"被大小排除/被采样排除/进入全量哈希"的文件数（已有部分，补齐展示）。
- **说明**：采样永远只用于剪枝，最终判定仍是全量哈希，这点不变。

### 2.4 扫描 · 优化 4：重复结果预览

- **需求原文**：结果页提供视频缩略图预览、支持片段播放，避免误删不同压制版本、花絮、不同剪辑版本。
- **结论**：**部分已实现 + 需补强**（缩略图/时间点/并排对比）。
- **现状**：视频已可用浏览器原生 `<video>` 播放且支持 Range 拖动；图片/文本/PDF 预览已有。
- **方案（v0044）**：
  1. `GET /api/preview/thumb?path=&t=<秒>&w=<宽>`：FFmpeg 抽 1 帧转 JPEG，落 `<var>/cache/thumbs/<sha1(path|size|mtime|t)>.jpg`，LRU 上限（默认 2000 张 / 200 MB），并发限制 1–2，超时回退占位图。
  2. 结果页视频组卡片显示 3–6 张时间点缩略图（按组内文件并列），点击缩略图 → 弹窗从该时间点播放（`video#t=`）。
  3. 弹窗支持"并排对比"：同一重复组的两个文件两个播放器，同步播放/独立播放切换。
  4. 相似/视频组卡片显示"时长、分辨率、音轨数、字幕轨数"（来自媒体探测缓存），帮助判断"不同压制版本"。
- **限制（必须写进 UI 提示）**：浏览器不支持 HEVC/MKV/DTS 等编码时无法播放 → 缩略图仍可见；可选"低码率转码片段"开关（额外 CPU，默认关）。
- **验收**：真机 4K WMV/MKV 抽帧成功；缩略图缓存命中不重复调 FFmpeg；超时/失败有占位图与原因。

### 2.5 扫描 · 优化 5：安全删除增强

- **需求原文**：硬链接替代删除（适配 Btrfs）；套件删除文件独立进入回收站，支持整组重复文件一键恢复；提供白名单，指定目录/后缀禁止删除，保护外挂字幕、nfo、海报等附属文件。
- **结论**：**可行，但硬链接的"可恢复"语义必须降级说明**。
- **方案（v0044）**：
  1. **硬链接合并（新操作，非删除）**：`POST /api/scans/{id}/merge-plan` + `POST .../merge`；对每个重复组选一个"主副本"，其余路径 `os.link(master, path)` 前先 `os.unlink(path)`（原子性用"先 link 到临时名 → rename 覆盖"保证不丢路径），记录 manifest（`<var>/merges/<job>.jsonl`）。只能同卷；跨卷跳过并说明。
     - 不可逆：合并后各路径共享内容，任一处修改全局生效。提供"复制为独立副本"（Btrfs `FICLONE` ioctl，回退 `shutil.copyfile`）作为补偿动作。
     - 默认关闭、逐组勾选、二次确认、审计。
  2. **套件独立回收站**：设置 `delete_recycle_mode = share_recycle | package_recycle`（默认 `share_recycle` 保持现状）。`package_recycle` 时移动到 `<共享根>/.duplicate-cleaner-trash/<时间戳>/<相对路径>`（同卷 rename，不复制），并在 `<var>/trash/` 写 manifest（原路径、大小、哈希、组 id、时间）。新增文件管理工具页：按批次/组查看、**整组一键恢复**（`POST /api/trash/restore`，逆 rename + 冲突处理）、清理（仅删套件回收站内、且二次确认）。
     - 为什么不用 `#recycle` 直放：DSM 回收站 UI 只认它自己的目录结构，手工塞进去的文件在 File Station 里可能不显示，也不便整组恢复。
  3. **删除白名单**：设置 `protect_extensions`（默认 `.srt/.ass/.ssa/.sub/.vtt/.nfo/.txt/.jpg/.jpeg/.png/.webp/.bif/.xml/.json`）、`protect_dirs`（目录前缀）、`protect_regex`。扫描阶段命中即标 `protected=true` → 不进入候选、不可勾选；**删除执行前再校验一次**（防止扫描后改名）。
  4. 摘要统计里显示"已保护 N 个文件"。
- **风险**：跨卷（volume1↔volume2）无法硬链接也无法 rename → 只能复制（大文件不可接受）→ 直接跳过并提示；隐藏目录 `.duplicate-cleaner-trash` 需加入扫描黑名单防止自扫。
- **验收**：同卷合并后 `stat` 显示 nlink 增加、`df` 释放空间；跨卷给出明确跳过原因；恢复后文件哈希一致。

### 2.6 扫描 · 新增 1：计划扫描（+ 通知）

- **结论**：**可行**。
- **方案（v0045）**：设置 `scheduled_scan_enabled`、`schedule_rules`（有序列表：每日/每周/间隔 + 时间窗）、`schedule_only_when_idle`（/proc/loadavg 低于阈值才跑）、`schedule_roots/excludes`（复用上次扫描范围或指定）。后端调度线程每 30 s 检查一次，触发即创建普通扫描任务（审计 user=`scheduler`）。完成后按通知设置推送。
- **限制**：
  - 套件服务停止时不触发（DSM 7 套件不是常驻 daemon）→ UI 明确提示；
  - 休眠/待机期间不触发；
  - 若需要"系统级定时"（套件没跑也能触发），要用 DSM 任务计划，本轮不做（避免写系统级任务）。
- **验收**：改系统时间/等待触发；负载高时跳过并记录原因；完成后收到通知。

### 2.7 扫描 · 新增 2：相似视频识别增强

- **结论**：**可行但有限度**（原文"识别源片一致、压制版本不同"可分档实现；"不同剪辑版本/花絮"不可承诺）。
- **现状能力**：抽帧 pHash + DTW + 时长比 + 安全团 + 可选 ASR 文本相似。
- **增强方案（v0046）**：
  1. 抽帧自适应：按分辨率/时长调整 `n_eff`；帧保存 64×64 灰度（提升缩放鲁棒性）；
  2. 黑边/信箱检测后裁边再算 pHash（不同压制常见黑边差异）；
  3. 归一化对齐：整体时间轴 ±2% 偏移搜索（DTW 已有，加强局部容差）；
  4. 时长比窗口分级（≥0.98 高置信 / 0.9–0.98 中 / <0.9 低）；
  5. **分档置信度**：高（≥95）/ 中（85–95）/ 低（<85，仅提示不进入删除候选）；UI 用颜色区分；
  6. 可选**轻量音频签名**（默认关）：FFmpeg 抽 8 kHz 单声道 60 s，按 1 s 能量包络 + 过零率生成 64 位签名，Hamming 距离比对；用于"画面被裁剪/加台标但音轨相同"的场景。代价：每文件多一次音频解码（约视频时长的 1–3%）。
- **明确不承诺**：片段 vs 完整长视频、不同剪辑、花絮、重拍；这些仍以人工预览（v0044 并排对比）为准。

### 2.8 扫描 · 新增 3：排除规则增强

- **结论**：**可行**（`.ignore` 做 gitignore 子集；符号链接已实现）。
- **方案（v0043）**：
  1. `exclude_name_regex`（多条正则，长度 ≤200，编译失败直接报错并定位到第几条）；
  2. `exclude_glob`（通配符，便于非技术用户）；
  3. `.ignore` 文件：枚举时若当前目录存在 `.ignore` 则读取（最多 1000 行），支持注释 `#`、空行、`dir/`、`*.ext`、`/abs-from-root`、`!` 否定（不实现 `**` 完整语义），命中即跳过该目录/文件；解析失败告警但继续；
  4. 影视库附属文件默认不参与判重：新增 `media_sidecar_mode`（`skip` 默认 / `include`），默认跳过 `.nfo/.srt/.ass/.jpg/.png/.bif` 等同名附属文件（避免"海报重复"污染结果），但用户可开启；
  5. UI 显示"被排除的目录/文件数"与命中的规则（便于排查"为什么没扫到"）。
- **限制**：`.ignore` 只做常用子集，不做完整 gitignore 语义（`**`、嵌套否定优先级）；`.ignore` 本身也可能被用户误放 → 只读取 root 及其子目录，不读系统目录。

### 2.9 字幕 · 补充：视频监控自动入队

- **结论**：**可行（轮询实现，不用 inotify）**。
- **方案（v0047）**：设置 `watch_dirs`（多个目录）、`watch_enabled`、`watch_interval_min`（默认 10，范围 1–60）、`watch_modes`（自动 ASR / 自动翻译 / 询问）。后端线程按间隔枚举目录（复用 `enumerate_videos`，跳过已有 `<stem>.srt` 与已有任务），发现新视频自动建任务（`source=watch`，审计可见），受并发与负载管控约束。可选"仅监控指定目录"及"新增总量上限（防误配大目录）"。
- **限制**：标准库无 inotify（ctypes 实现受 watch 数量限制且网络盘不可靠），所以用轮询 → 延迟 = 间隔；大目录枚举耗时需限制（每次最多 N 个目录/文件）；套件停止期间不监控。

### 2.10 字幕 · 优化 1：失败任务智能重试与归类

- **结论**：**可行**。
- **方案（v0047）**：
  1. 失败分类表（code → 类别 → 可重试）：
     | 类别 | code | 可重试 |
     |---|---|---|
     | 音频提取失败 | `AUDIO_FAILED` `INVALID_VIDEO` `NO_DURATION` | 否（换文件） |
     | 无语音 | `NO_SPEECH` | 否（过滤） |
     | 码流不支持 | `FFMPEG_UNAVAILABLE`（针对单文件解码失败时改码） | 否 |
     | 超时 | `TIMEOUT` `PROVIDER_TIMEOUT` | 是（退避 3 次） |
     | 网络异常 | `NETWORK_ERROR` `PROVIDER_NETWORK_ERROR` `HTTP_ERROR 5xx` | 是（退避 3 次） |
     | 权限异常 | `OUTPUT_NOT_WRITABLE` 类（目前是 warning）/ `PERMISSION` | 是（修权限后重试） |
     | 凭据/配额 | `PROVIDER_AUTH_FAILED` `PROVIDER_REJECTED 4xx` | 否（需改设置） |
     | 内部错误 | `INTERNAL_ERROR` | 是（1 次） |
  2. 自动重试：任务失败时判类别，可重试则 `retry_attempts+1`，指数退避（30 s / 2 min / 10 min）后重新入队；不可重试直接 `failed` 并写 `failure_category`。
  3. "无语音"前移：批量提交可选"提交前静音预检"（FFmpeg `silencedetect`/`volumedetect`，成本高，默认关闭）；ASR 空结果仍归 `NO_SPEECH` 且计入"已过滤无语音"统计。
  4. UI：任务列表显示失败类别徽标 + 失败明细（错误码/消息/时间/尝试次数）；"失败清单"页支持筛选、**导出 CSV/JSON**、**批量重新识别**（按类别选择，走现有 batch-groups 机制）。
- **验收**：模拟网络失败自动重试至成功；无语音任务不计入重试；导出清单字段完整。

### 2.11 字幕 · 优化 2：任务调度、限速与资源管控

- **结论**：**可行**（NAS 侧负载阈值；远端 ASR 负载可选）。
- **方案（v0047）**：
  1. 资源守卫线程每 15 s 采样 `/proc/loadavg`（1 分钟负载）与 `/proc/stat`（CPU 使用率），可配 `subtitle_load_max`（默认 0=关闭；建议值 = 核数 × 0.8）、`subtitle_cpu_max_percent`；
  2. 超阈值 → `paused_by_load=true`：**不再取新任务**（运行中任务不中断），任务列表显示"因系统负载暂停取任务"；低于阈值自动恢复；
  3. 优先级：`GET/POST /api/subtitles/{id}/priority`（手动置顶/上移）、`subtitle_dir_priority`（目录前缀 → 优先级 0–10，提交时快照到任务）；队列实现从 `deque` 改为按 `(priority, submit_seq)` 排序的小顶堆（或分段 deque，保持现有 FIFO 语义不变）；
  4. ETA 优化：ASR 阶段用"分片真实耗时 × 剩余片数"（已有）再叠加"当前并发/队列位置"分摊；翻译阶段用批次均值（已有）。补"队列预计开始时间"（前面任务 ETA 之和 / 并发数）。
- **限制**：ASR/翻译在远端服务器（10.10.10.233）→ NAS 负载阈值只反映 NAS 侧；可选的"远端 ASR `/health` 探测"不是标准 OpenAI 接口，做成可选探测（失败即忽略）。
- **验收**：`stress` 造高负载 → 队列停止取任务、运行中任务不受影响；降负载自动恢复；置顶任务下一个执行。

### 2.12 字幕 · 优化 3：音轨选择

- **结论**：**可行**（无语言标签时只能按序号）。
- **方案（v0047）**：
  1. 扩展 `FFmpegTool.probe_media`：解析 `Stream #0:N(lang): Audio: codec, ... , channels` 与 `Subtitle:` 行，返回 `audio_streams=[{index, stream_index, codec, language, channels, title, default}]`、`subtitle_streams`；
  2. 任务/批次提交参数 `audio_track`（`auto` 默认 / `index:<stream_index>` / `lang:<code>` / `first`），快照到任务；
  3. 抽音频参数从 `-map 0:a:0` 改为按选择映射（`-map 0:<stream_index>`），server 模式同样支持；
  4. UI：提交弹窗"音轨"下拉（探测后列出）；批量提交可选"按语言优先，缺失时用首音轨"；
  5. 任务详情显示实际使用的音轨（索引/语言/编码），便于排查"识别到配音"。
- **限制**：语言标签依赖容器元数据，很多文件没有 → 只能序号；"配音/原声"判断不能自动保证。

### 2.13 全局 · 1：任务检索筛选与批量操作

- **结论**：**可行**。
- **方案（v0048）**：
  - `GET /api/tasks`（或扩展现有列表）：统一筛选 `status`、`dir`（目录前缀）、`ext`（后缀）、`failure_category`、`q`（路径/任务 ID 模糊）、时间范围；服务端 SQL 分页（字幕任务表加 `path_prefix`、`extension`、`failure_category` 列或生成列 + 索引）。

### 2.14 全局 · 2：权限与路径向导

- **结论**：**部分做不到（自动配置），可做"体检 + 指引"**。
- **为什么做不到**：套件后端以 `duplicatecleaner` 非 root 运行，`chmod/chown/setfacl` 对共享文件夹无效；DSM 没有向第三方套件开放的提权接口（无 sudo/polkit）；SPK 脚本虽然是 root，但只在安装/启动瞬间运行，不能作为常驻提权通道。
- **方案（v0048）**：`GET /api/permissions/check`：
  1. 枚举共享文件夹与已配置扫描/字幕根目录；
  2. 逐项检查：目录是否可读（`os.scandir` 尝试）、是否可写（创建 `.dc-write-test` 临时文件后立即删除，失败即判不可写）、是否加密且未解锁、是否只读挂载、套件用户是否存在、父目录 ACL；
  3. 输出问题清单（路径 / 问题类型 / 影响的功能 / 严重级别 / 解决指引），并汇总"无法读取文件清单"（扫描期权限失败也计入，已有 `skipped.permission` 计数，补齐明细）；
  4. 生成操作指引：DSM 界面路径（控制面板 → 共享文件夹 → 编辑 → 权限 → 系统内部用户 → duplicatecleaner）+ 可选 `synoacltool` 命令文本供管理员 SSH 执行（**只显示、不执行**）。
- **限制**：不能真正改权限；不能检测"将来才会出现"的权限问题（只能测当前路径）。

## 3. 做不到 / 不合适的详细说明

### 3.1 套件运行期自动配置共享文件夹权限 —— 做不到

- 事实：后端进程用户 `duplicatecleaner`，无 root、无 sudo；DSM 未提供第三方套件提权 API。
- 影响：需求"提供权限配置一键向导，快速配置共享文件夹读写权限"中的"自动配置"部分无法实现。
- 替代：权限体检 + 精确指引（§2.14）。如果确实要"一键"，只能让管理员通过 SSH/DSM 任务计划以 root 执行一段脚本——这超出套件权限模型，不建议内置（会把"套件能改系统权限"变成安全风险）。

### 3.2 增量扫描"仅对比新增/修改文件" —— 不可行

- 会漏检：新文件 vs 未变化旧文件（最常见）、旧文件被修改后变重复、旧文件被删除/重命名。
- 替代：哈希缓存（内容未变不重算）+ "仅看本次新增重复"视图。见 §2.1。

### 3.3 相似视频"识别不同剪辑版本/花絮" —— 不可承诺

- pHash+DTW 能处理：同源不同分辨率/码率/封装、整体轻微时间偏移、不同黑边。
- 不能可靠处理：重新剪辑（顺序/时长变化）、加片头片尾、花絮与正片混剪、不同语言配音且画面被裁、旋转/镜像。
- 替代：分档置信度 + 并排预览 + 强制人工复核（现有门禁保持不变）。

### 3.4 "视频缩略图/片段播放"的编码限制 —— 需明确降级

- 浏览器不能解码 HEVC/VC-1/DTS/AC3 等 → 无法播放（缩略图仍可看）。
- 替代：缩略图 + 时间点播放 + 可选低码率转码片段（默认关，CPU 代价）；否则引导"在 File Station/播放器打开"。

## 7. 明确不做
