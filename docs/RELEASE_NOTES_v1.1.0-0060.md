# 发布说明 · v1.1.0-0060

> 主题：字幕默认译文 · 设置页瘦身 · 通知渠道调整（移除 DSM）
> 升级方式：套件中心手动安装覆盖升级；数据目录、包 ID 与 SQLite schema（v11）不变。

## 1. 字幕任务默认勾选「同时生成译文」

- 只要已配置 **LLM API Key**，单文件弹窗与批量弹窗的「生成译文」默认勾选；用户手动取消后不会被重置。
- 未配置 LLM Key 时复选框禁用且不勾选，提示先配置。
- 目录监控、下载/转换完成后的自动字幕任务同样默认翻译（跟随 LLM Key）。
- `subtitle_translate_enabled` 降级为兼容键（默认 `true`、不再生效）；后端只在缺 LLM Key 时返回
  `400 TRANSLATE_NOT_CONFIGURED`，`TRANSLATE_DISABLED` 不再出现。
- 设置页删除「生成译文」总开关；翻译目标语言仍可在任务弹窗选择。

## 2. 设置页精简（约 150 → 约 44 个可见项）

- 删除与扫描页完全重复的「扫描 / 相似 / 视频 / 存储」四组。
- 下载、转换、合成只保留默认输出位置；字幕只保留凭据、识别语言、默认音轨与目录监控；
  通知只保留渠道/事件/凭据与释放空间阈值。
- 超时、并发、模板、限速、任务上限等纯参数改为后端固定默认（沿用原默认值），
  **后端设置键、校验与 `GET/PUT /api/settings` 全部保留**：已有配置值继续生效，
  只是不再出现在设置页；「恢复默认值」会把隐藏键一并复位。
- 设置页最终分组：媒体与外部工具 / 自动化 / 云端字幕 / 下载 / 转换 / 合成 / 安全 /
  系统诊断 / 权限体检。

## 3. 通知：移除无效的「DSM 系统通知」渠道

- 结论：DSM 7 的系统通知要求套件通过 `conf/resource` 的 `sysnotify` 注册 i18n 文案，
  而该资源 worker **仅对 Synology 自家套件开放**。第三方 SPK 一旦声明，Package Center
  会以错误 4539「该套件使用 Synology 套件专属的资源」拒绝安装（真机实测）。
- 因此 v0060 移除 DSM 渠道、`spk/ui/texts` 与 `sysnotify` 资源；设置页只保留
  Webhook / Telegram 两个渠道与对应测试按钮。
- 旧配置里的 `notify_channels: ["dsm"]` 会被静默忽略，不会报错；需要外部提醒请配置
  Webhook 或 Telegram。
- 附：`synodsmnotify` 本身的正确调用已实测（`-c <app_id> -l <level> <用户> <已注册 tag> '<json>'`），
  但受资源限制，第三方套件无法注册自己的文案。

## 4. 兼容性

- API、schema（v11）、包 ID、数据目录不变；升级保留全部设置与任务记录。
- 旧客户端若仍提交 `subtitle_translate_enabled` / 被精简的设置键，不会 400（键仍在校验白名单）；
  `notify_channels` 里的 `dsm` 会被忽略（渠道已移除）。
- 隐藏设置项若曾改过值，升级后继续按该值运行，但无法再从设置页修改。

## 5. 验证

- unittest、static、e2e 结果见 `qa/REPORT.md` 的 v0060 段。
- 安装后可在「设置 → 自动化 → 测试 Webhook / 测试 Telegram」验证外部通知；
  DSM 通知渠道已移除，不会再出现在设置页。
